TESTING QA · PROYECTO 01

Documentación del proyecto

E-commerce Simulation. Documentación del trabajo realizado durante las actividades de testing manual, incluyendo plan de pruebas, casos de prueba, testing exploratorio, reportes de errores, evidencias y oportunidades de mejora.

01. Plan de pruebas

Plan de pruebas

Objetivo

Evaluar la funcionalidad del proceso y gestión de compra de un producto, validando que el producto cumpla con las necesidades del cliente/usuario y reduciendo la probabilidad de defectos en el desarrollo.

Alcance

Aseguramiento de calidad de un proyecto en desarrollo, validando funcionalidades específicas. Se contemplan aspectos funcionales, de usabilidad y rendimiento.

Equipo de trabajo

Un tester junior, trabajando de manera remota desde Argentina.

Estrategia de pruebas

  • Pruebas funcionales manuales.
  • Pruebas no funcionales.
  • Pruebas de usabilidad.
  • Pruebas de rendimiento.
  • Pruebas exploratorias en Sign-Up.

Criterios de prueba

Requisitos funcionales y no funcionales relacionados con usabilidad, rendimiento, seguridad, accesibilidad, estabilidad y recuperación.

Entorno de pruebas

  • Equipo: HP Notebook.
  • Sistema operativo: Windows 10.
  • Navegador: Google Chrome.

Entregables

  • Plan de pruebas.
  • Informe de estado.
  • Reportes de defectos.
  • Reportes de mejora.

Gestión de incidentes

Documentar cada desviación detectada, incluyendo descripción, pasos para reproducirla, entorno, severidad y evidencia (capturas de pantalla o registros). La prioridad se determina según la severidad y el impacto.

Gestión de riesgos

Riesgo Probabilidad Impacto Mitigación Contingencia
Falta de tiempo para completar las pruebas. Media Alto Priorizar los casos según riesgo y criticidad. Trabajar horas adicionales.
Impacto en la moral del equipo. Baja Medio Generar un ambiente de trabajo colaborativo y de apoyo. Celebrar pequeños logros y brindar apoyo continuo.

Lista de tareas

  • Crear casos de prueba.
  • Ejecutar pruebas funcionales.
  • Ejecutar pruebas no funcionales.
  • Realizar reporte de defectos.
  • Realizar reporte de mejora.

03. Testing exploratorio

Testing exploratorio

Objetivo

Evaluar la funcionalidad y usabilidad del proceso de registro de usuarios.

Alcance

Verificar que los usuarios puedan registrarse sin inconvenientes y que el sistema gestione correctamente distintos escenarios.

Preparación

  • Verificar que el servidor y la plataforma estén operativos.
  • Contar con un navegador actualizado y un sistema operativo compatible.
  • Preparar diferentes correos electrónicos, nombres de usuario y contraseñas para las pruebas.

Datos de prueba

Conjunto de datos Tipo de datos Descripción
Datos 1 Falsos Datos ficticios para realizar pruebas de registro.
Datos 2 Verdaderos Datos correspondientes a un usuario real.
Datos 3 Falsos Datos ficticios para realizar pruebas adicionales.

Resultados esperados

  • Los usuarios pueden completar el registro.
  • El sistema gestiona los errores y proporciona mensajes útiles.
  • La cuenta se activa y el usuario puede iniciar sesión.

Ejecución de pruebas exploratorias

ID Prueba Resultado esperado Resultado obtenido
001 Acceder a la página de registro desde el enlace. Acceder correctamente al formulario de registro. Se pudo acceder al formulario.
002 Dejar campos incompletos. No permitir el registro. El sistema solicitó Username y Password.
003 Completar campos con caracteres y datos como 12121213. No permitir el registro. Permitió el registro. No solicitó nombre, apellido ni Gmail.
004 Registrarse con datos falsos. No permitir el registro con datos ficticios. Permitió el registro con datos falsos.
005 Registrarse con datos de un usuario real. Permitir el registro. Se registró sin intervención adicional.
006 Intentar registrarse con un usuario existente y otra contraseña. No permitir el registro. No fue posible porque el usuario ya existía.
007 Iniciar sesión con los usuarios creados, utilizando datos válidos e inválidos. Permitir el acceso con datos válidos y rechazar datos inválidos. Se podía registrar e iniciar sesión con cualquier dato. Con los datos 3 (12121213), apareció una advertencia sobre el cambio de contraseña, pero se permitió continuar navegando.
04. Reportes de errores

Reporte de errores generales

Error 1: La pantalla del usuario se bloquea al presionar la opción "Contact"

Descripción: Al navegar desde Contact hacia Sign-Up, la página se volvía transparente y no permitía continuar utilizando el sitio. Luego de actualizar varias veces, el problema desaparecía.

Pasos para reproducir:

  1. Registrarse en la plataforma.
  2. Ir a la página de inicio.
  3. Navegar hacia la opción Contact.

Resultado esperado: Poder navegar normalmente.

Resultado obtenido: La página desaparece y no permite navegar hasta actualizarla.

Severidad: Alta.

06. Oportunidad de mejora

Falta de un "buscador"

Fecha: 22 de julio de 2024.

Autor: Gonzalo Jesus Godoy.

Problema

No existe una función de búsqueda que permita encontrar productos específicos dentro del sitio.

Objetivo

Mejorar la utilización del sitio. Un buscador facilita encontrar el producto requerido.

Mejoras propuestas

  • Agregar un campo de búsqueda visible en la página principal y en todas las páginas de categorías.
  • Incorporar sugerencias automáticas en tiempo real mientras el usuario escribe.
  • Agregar filtros avanzados, como categoría, precio, marca, entre otros.

Beneficios esperados

  • Los usuarios podrán encontrar productos por descripción o precio.
  • Se mostrarán resultados relevantes.
  • Se facilitará la búsqueda de productos.

Impacto en el proyecto

La implementación y el mantenimiento requieren recursos de desarrollo y testing, además de capacitación de soporte. Se espera un efecto positivo en el tráfico y las ventas debido a la mejora en la usabilidad.

Pruebas propuestas

  • Pruebas funcionales del buscador y los filtros.
  • Pruebas de usabilidad.
  • Pruebas de rendimiento.

Estado

Opciones de estado: Pendiente, En Progreso, Completado o Rechazado.
