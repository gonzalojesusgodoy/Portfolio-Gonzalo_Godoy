# QA Manual, Testing de APIs y Rendimiento | DemoGuru

Proyecto práctico de **Software Testing**, enfocado en la evaluación funcional de la plataforma de demostración DemoGuru, complementando las pruebas manuales con prácticas de testing de APIs y pruebas de estrés.

El trabajo comprende el diseño y ejecución de casos de prueba, la identificación y clasificación de defectos y la evaluación de diferentes aspectos del comportamiento del sistema.

## Objetivo y estrategia de prueba

Evaluar el funcionamiento de las principales funcionalidades de la plataforma mediante diferentes escenarios de prueba, identificando posibles defectos y documentando los resultados obtenidos.

La práctica también contempla la exploración de servicios API y el análisis del comportamiento del sistema ante condiciones de exigencia.

**Características del proyecto:**

| Aspecto | Descripción |
|---|---|
| Plataforma | DemoGuru |
| Enfoque | QA Manual y Software Testing |
| Pruebas funcionales | Evaluación de funcionalidades e interfaz |
| Testing de APIs | Pruebas de servicios y endpoints |
| Testing no funcional | Pruebas de estrés |
| Técnicas de diseño | Partición de equivalencia y análisis de valores límite (BVA) |
| Escenarios | Positivos y negativos |

## Alcance técnico y actividades

### 1. Pruebas funcionales y diseño de casos de prueba

Diseño y ejecución de escenarios para evaluar el comportamiento de las principales funcionalidades de la plataforma.

- Elaboración de casos de prueba.
- Definición de escenarios positivos y negativos.
- Evaluación de diferentes datos de entrada.
- Comparación entre resultados esperados y obtenidos.
- Registro de resultados de ejecución.

### 2. Identificación y gestión de defectos

Documentación y clasificación de los errores identificados durante las pruebas.

- Identificación de comportamientos inesperados.
- Elaboración de reportes de bugs.
- Registro de pasos para reproducir los defectos.
- Documentación de resultados esperados y obtenidos.
- Clasificación de defectos según su tipo y criticidad.

### 3. Testing de APIs

Práctica orientada a la evaluación de servicios de API, explorando el intercambio de información entre las solicitudes y las respuestas del sistema.

- Exploración de solicitudes a endpoints.
- Evaluación de métodos HTTP.
- Revisión de códigos de estado.
- Inspección de respuestas en formato JSON.
- Análisis del comportamiento de los servicios.

### 4. Pruebas de estrés y rendimiento

Evaluación del comportamiento de la aplicación ante diferentes condiciones de exigencia.

- Realización de pruebas de estrés.
- Observación del comportamiento del sistema durante las pruebas.
- Análisis de posibles dificultades de rendimiento.
- Documentación de los resultados obtenidos.

## Metodología de trabajo

El proyecto se desarrolló mediante un proceso organizado en diferentes etapas:

1. **Diseño:** definición de escenarios y elaboración de casos de prueba.
2. **Ejecución:** realización de pruebas funcionales y registro de resultados.
3. **Análisis:** identificación de comportamientos inesperados y posibles defectos.
4. **Documentación:** elaboración de reportes y clasificación de hallazgos.
5. **Evaluación complementaria:** realización de prácticas de testing de APIs y pruebas de estrés.

## Competencias y aprendizajes

Esta práctica permitió trabajar sobre diferentes aspectos del proceso de QA Manual y ampliar los conocimientos sobre evaluación de software.

Entre los principales aprendizajes se destacan:

- **Diseño y ejecución de pruebas:** elaboración de escenarios positivos y negativos y análisis de resultados.
- **Gestión de defectos:** identificación, documentación y clasificación de errores.
- **Testing de APIs:** aproximación a la evaluación de servicios y respuestas HTTP.
- **Testing no funcional:** exploración del comportamiento del sistema mediante pruebas de estrés.
- **Documentación técnica:** organización de evidencias y resultados para facilitar el análisis de los hallazgos.
