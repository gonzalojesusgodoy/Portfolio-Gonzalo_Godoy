# Metodologia Agil "Coderhouse"

## Contexto y Rol

Este proyecto fue realizado durante mi formación en Coderhouse como una práctica para aplicar conocimientos sobre metodologías ágiles.

El objetivo principal fue experimentar con diferentes formas de organizar y visualizar el trabajo, utilizando conceptos de Scrum y Kanban.

Mi participación estuvo enfocada en la organización y seguimiento del trabajo, utilizando un tablero para visualizar las tareas, controlar su estado y analizar cómo avanzaba el proyecto.

## El Problema

Uno de los principales desafíos era organizar las diferentes tareas del proyecto y poder visualizar claramente su estado.

A medida que se incorporaban actividades, era necesario saber qué tareas estaban pendientes, cuáles se encontraban en ejecución, cuáles estaban siendo revisadas y cuáles ya habían sido terminadas.

También era importante evitar comenzar demasiadas tareas al mismo tiempo, ya que esto podía generar una acumulación de trabajo y dificultar el avance del proyecto.

Por este motivo, se buscó implementar una forma de trabajo que permitiera visualizar el flujo, organizar las tareas y detectar posibles demoras o puntos de saturación.

## Mi Proceso — Análisis y decisiones

Para abordar el problema se decidió experimentar con Scrum y Kanban, utilizando cada enfoque en una parte del proyecto.

La utilización de un tablero visual permitió representar las tareas mediante tarjetas y moverlas entre diferentes estados a medida que avanzaba el trabajo.

En la parte gestionada mediante Kanban se estableció un límite WIP (Work In Progress) para controlar la cantidad de tareas que podían encontrarse simultáneamente en ejecución.

Esta decisión permitió mantener un margen de trabajo y evitar que el flujo se saturara con demasiadas tareas abiertas al mismo tiempo.

Durante el desarrollo también se utilizaron métricas para observar el comportamiento del flujo e identificar situaciones que podían mejorarse.

Una de las principales ventajas de este enfoque fue que permitió pasar de una visión general del proyecto a una representación más concreta de qué tareas estaban pendientes, cuáles estaban siendo trabajadas y dónde podían aparecer demoras.

## La Solución

La solución consistió en implementar un sistema de gestión visual del trabajo, utilizando un tablero dividido en diferentes estados.

Las tareas fueron organizadas en columnas que representaban su avance, permitiendo visualizar el recorrido de cada actividad desde que estaba pendiente hasta su finalización.

El tablero permitió trabajar con estados como:

- Backlog
- To Do
- In Progress / Doing
- Testing / Review
- Done

Además, en la columna de trabajo en progreso se utilizó un WIP de 2, limitando la cantidad de tareas que podían estar siendo ejecutadas simultáneamente.

De esta manera, el tablero permitió tener una visión más clara del flujo de trabajo y detectar cuándo las tareas comenzaban a acumularse en determinadas etapas.

## Impacto / Resultados

La implementación del tablero permitió visualizar de una manera más sencilla cómo podía organizarse y seguirse el trabajo dentro del proyecto.

El uso del límite WIP permitió experimentar con una forma de controlar la cantidad de tareas en ejecución y evitar comenzar demasiadas actividades simultáneamente.

Las métricas utilizadas durante la práctica también permitieron analizar el flujo e identificar puntos que podían mejorarse.

Entre los principales aspectos detectados se encontraron:

- Falta de información necesaria para avanzar.
- Tiempos de espera.
- Demoras generadas durante las revisiones.

Sin embargo, este proyecto fue realizado como una práctica de aprendizaje y no representa una implementación de Scrum o Kanban en un entorno productivo real. Por este motivo, los resultados se presentan como observaciones obtenidas durante el ejercicio y no como mejoras de rendimiento comprobadas.

## Reflexión y aprendizaje

Este proyecto me permitió llevar los conceptos de Scrum y Kanban de la teoría a una situación práctica.

Uno de los principales aprendizajes fue comprender la importancia de visualizar el trabajo. Tener las tareas representadas en un tablero permitió entender mejor el estado del proyecto y detectar situaciones que podían pasar desapercibidas si solamente se observaba la lista de actividades.

También comprendí la utilidad de establecer límites al trabajo en progreso. El WIP permitió experimentar con una forma de evitar comenzar demasiadas tareas al mismo tiempo y mantener un flujo de trabajo más controlado.

Además, aprendí que las métricas no solamente sirven para medir resultados, sino también para detectar problemas y encontrar oportunidades de mejora.

Este proyecto fue importante para mi formación porque me permitió experimentar con diferentes formas de organización y comprender que una metodología no consiste solamente en seguir pasos, sino en utilizar herramientas y criterios que ayuden a organizar, visualizar y analizar el trabajo.
